### 扫描与连接要求 APP-01

- 列表显示设备名、完整地址、RSSI和最近发现时间，以地址合并同一设备。名称优先取非空`ScanRecord.deviceName`，再使用设备缓存名；后续广播带来名称时更新旧行，空名称不覆盖已有有效名称。
- 调试扫描不因空名称、名称大小写或未广播目标服务UUID而丢弃设备。广播服务列表与连接后发现的GATT服务分别展示；当前测试地址不能写死为全部设备身份。
- 保留返回列表时的扫描结果，不因页面进出自动重扫或重排编号；重新扫描须由用户明确触发，并清空或明确标记旧结果，避免重叠扫描。
- 区分扫描中、结束、无结果、失败、蓝牙关闭和权限缺失；RSSI无效值127显示为未知，不能当作信号最强。
- 连接中、服务发现、接收初始化、可收发、断开和失败分别反馈；断开后立即撤销就绪状态，重连后重新初始化监听。权限实现按实际目标Android版本处理。

### 基础透传对接要求 APP-02

阶段为F06-P01，只验证原始字节透传，不加入校时、设置、历史或OTA业务帧。手表验收固件为`F06-P01-20261115-01`，界面为`BLE UART CHECK`；后续若改用其他固件，重新确认行为和样例。测试时其他App须断开同一设备。

| 项目 | 当前实测参数 |
| --- | --- |
| 模块与名称 | TEL0073 BLE-Link；SmartWatch |
| 当前测试地址 | `0C:B2:B7:4E:A2:35`，仅用于识别本台实物 |
| 服务 | `0000dfb0-0000-1000-8000-00805f9b34fb` |
| 串口数据DFB1 | `0000dfb1-0000-1000-8000-00805f9b34fb`，用于数据写入和接收监听 |
| 命令DFB2 | `0000dfb2-0000-1000-8000-00805f9b34fb`，用于核对原厂初始化，不作普通数据通道 |

**通知兼容。** 本台模块DFB1、DFB2均显示Notify/Read/Write/Write No Response，但服务发现未提供CCCD `0x2902`；nRF Connect开启通知失败。2026-11-18原厂BlunoBasicDemo已实测收到手表回显及主动发送，因此不能据此判断硬件链路不能回传，也不能把该兼容问题推广到所有版本模块。

手机端对照原厂[串口回显示例](https://wiki.dfrobot.com/tel0073/docs/22558)及本仓库[BlunoLibrary.java正文](references/text/26_BLE_官方Android示例_BlunoLibrary.java.txt)、[BluetoothLeService.java正文](references/text/26_BLE_官方Android示例_BluetoothLeService.java.txt)，核对命令通道初始化和DFB1本地通知监听。原厂示例调用`setCharacteristicNotification`，CCCD写入代码被注释；哪些初始化步骤为本台模块必需仍须验证，不能推定只调用一个API就必定成功。存在2902时走标准订阅；缺失时使用经实测的兼容流程，不直接判为连接失败。初始化读写按回调顺序执行，不盲目复制修改密码、波特率等命令，也不为此直接升级模块固件。

**字节与队列。** 收发保留原始ByteArray，接收处理`onCharacteristicChanged`的实际数据；不得先转字符串再恢复字节，不自动追加换行/结束符。发送串行排队，单次写入长度与分片依据实际能力确定；一次通知、一次写入或一次UART读取均不能当成业务帧边界。20字符回显通过不证明20字节是传输上限。分别记录提交发送、GATT写入完成和实际回显，API返回成功不等于手机已收到数据。

**临时调试入口。** 在现有设备详情页提供HEX输入及单次发送、HEX接收内容/长度/时间、本次连接累计收发字节数、清空及复制记录、初始化失败阶段与错误提示。重连后区分历史与本次数据；调试入口可在正式版本隐藏，但实际收发及错误反馈须保留。

| 编号 | 操作 | 通过标准 |
| --- | --- | --- |
| A01 | 手机发`31 32 33 34`一次 | 手机收到相同4字节，手表RX/TX各增加4 |
| A02 | 手表亮屏BLE页短按MENU一次；熄屏时先唤醒 | 手机收到`57 41 54 43 48 20 42 4C 45 0D 0A`，共11字节 |
| A03 | 手机发`00 FF 0D 0A 31 32 33 34`一次 | 收到相同8字节，无截断、转码、增删或重复 |
| A04 | 手机发ASCII `0123456789ABCDEFGHIJ` | 接收合计20字节且内容、顺序一致；允许分多次回调到达 |
| A05 | 主动断开后重新连接，再执行A01、A02 | 无需复位手表即可恢复双向收发，接收监听重新建立 |
| A06 | 手表自动熄屏后执行A01 | 手机收到相同回显，手表保持熄屏 |

每项交付实际发送/接收HEX、长度和结果。原厂APK目前已通过短文本回显、手表主动发送、主动断开重连、熄屏回显及20字符显示检查；未逐字节确认CR/LF、任意二进制或吞吐。队友APK A01—A06尚未验收。手表TX计数只证明UART发送，文本截图也不能替代原始字节比较。手机蓝牙关闭、超距掉线和后台/锁屏恢复仍需后续实机回归，不算本次主动重连已覆盖。

## 手机与手表的接口清单

方向以手机为参照。表中字段为双方必须协商覆盖的信息，尚不是字节布局。除接口准备阶段外，手机端不依赖STM32内部函数或内存结构，不直接把C结构体当作通信数据。

| 逻辑接口 | 方向 | 请求/事件内容 | 应答/上报内容及约束 |
| --- | --- | --- | --- |
| 设备信息 `DeviceInfo` | 请求→应答 | 查询设备信息 | 稳定设备标识、硬件型号/版本、App固件版本、协议版本、支持能力；OTA另需镜像兼容与Boot能力信息，确切字段待冻结 |
| 当前状态 `GetStatus / StatusChanged` | 查询→应答；手表→手机 | 查询状态；是否周期订阅及其频率待定 | 时间与有效性、日期对应的步数、电池mV及估算%、心率bpm、估算血氧%、各测量有效性、更新时间；若要展示接触质量须增加质量状态定义，不能由手机猜测 |
| 校时 `SetTime` | 请求→应答 | UTC Unix秒（1970-01-01 00:00:00起点）；2026-11-07用户确定本地固定北京时间UTC+8，不使用夏令时 | 成功/失败及设备实际保存时间；本地显示、日期切换与按日步数统一使用UTC+8，不随手机时区变化 |
| 参数读取 `GetSettings` | 请求→应答 | 查询当前参数 | 定时提醒设置、低活动提醒时长及可支持范围/版本；支持启用开关、数量和默认值须共同确认 |
| 参数保存 `SetSettings` | 请求→应答 | 需要修改的提醒参数 | 参数是否合法、是否持久化成功、实际保存值；不能只依据BLE写入成功就判断参数保存成功 |
| 历史查询 `GetHistory` | 请求→分页应答 | 游标/起始记录、页大小；日期过滤是否由设备支持待定 | 记录唯一标识、类型、时间、值及单位/有效性、下一游标和结束标志；约定覆盖环形存储后游标失效行为，不能默默跳过 |
| 求助事件 `SafetyEvent` | 手表→手机 | 事件ID、来源（手动/跌倒）、发生时间及有效性、阶段（待确认/已发起/已取消等） | 手机按ID去重并更新阶段；断线期间是否存储、如何补报及去重生命周期待约定 |
| 接收确认 `EventAck` | 请求→应答 | 已收到的事件ID | 只证明手机收到设备事件，不证明用户拨号/短信发送或接收方送达；ACK与重传规则待冻结 |
| 升级开始 `OtaBegin` | 请求→应答 | 镜像目标硬件、版本、长度、整包CRC；镜像头格式待定 | 是否可升级、拒绝原因、支持片长和设备确认的接收偏移；设备端负责容量及兼容性判断 |
| 升级分片 `OtaChunk` | 请求→应答 | 本包偏移、实际数据长度和数据 | 设备确认的连续接收偏移/失败原因；重传重复包应可识别，片长受实际传输能力约束 |
| 升级查询 `OtaQuery` | 请求→应答 | 查询当前升级会话 | 当前镜像标识、状态、已确认偏移、错误；只有同一镜像才能续传，不能仅依据手机本地进度恢复 |
| 升级结束 `OtaFinish` | 请求→应答及重连查询 | 请求完整校验并进入升级流程 | 校验结果、是否进入重启/安装、失败原因；最终成功以重连后的设备版本和升级结果确认，传输100%不等于升级成功 |

手机本地联系人、CSV保存分享、短信/拨号调用属于手机内部接口，不经BLE上传联系人或伪造送达回执。手表离线能完成本地提示；手机未连接时不能保证实时求助，恢复连接后的事件补报行为须按协议确认。

## 双方交付与联调边界

手机端负责人交付Android工程、可安装APK、对应源码版本、支持的系统范围及尚未支持的接口；手表端提供对应固件版本、真实BLE通道参数、双方确认的帧与载荷定义、可复算的收发样例和功能状态。样例作为本节正式接口说明维护，不另留临时测试报告。

建议联调顺序：设备连接与信息查询 → 状态和校时 → 提醒参数 → 历史和CSV → 健康状态 → SOS/跌倒 → OTA。各接口先确认正常及失败应答，再验收断线/重连和重复消息；手机端可提前独立完成UI与本地功能，不据此宣称整机联调通过。每次联调须对应明确的APK与固件版本，任务状态仍由原计划表维护。
