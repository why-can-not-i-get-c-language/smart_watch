## 手表界面与操作入口

2026-11-22用户要求先整合现有界面，再推进F08-P02电量估算与低电提醒。日常入口采用汇总主页、功能菜单与工具菜单，替代全部验收页逐个循环。

- 主页显示日期时间、本次开机累计步数和当前有效电池电压。步数不是每日汇总；F08-P02接入前不显示估算百分比。时间无效或电压采集异常时明确显示未设置或不可用。
- 主页短按MENU或长按KEY进入功能菜单，提供步数、历史和工具入口；主页长按MENU仍可设置时间。
- 菜单短按KEY选下一项、短按SOS选上一项、短按MENU进入，长按KEY返回上层。工具收纳电池ADC、PPG、MPU、姿态、BLE、振动、参数和Flash检查。
- 详情页长按KEY返回所属菜单，原MENU/SOS功能保留。时间编辑中保留加减、切字段、保存及取消，长按KEY不切换页面。
- 导航按键只负责导航，进入BLE或振动详情不能同时发送测试消息或启动振动；进入历史、参数及Flash页面不能自动写入或启动测试。原熄屏、完整唤醒按键消费和掉屏恢复继续适用。

手机端对照原厂[串口回显示例](https://wiki.dfrobot.com/tel0073/docs/22558)及本仓库[BlunoLibrary.java正文](references/text/26_BLE_官方Android示例_BlunoLibrary.java.txt)、[BluetoothLeService.java正文](references/text/26_BLE_官方Android示例_BluetoothLeService.java.txt)，核对命令通道初始化并实现DFB1本地通知监听。原厂示例调用`setCharacteristicNotification`，CCCD写入代码被注释；通过实测确定所需初始化步骤，不直接照搬示例中的密码和波特率写入。存在2902时走标准订阅，缺失时走兼容流程。初始化读写按回调顺序执行，保持现有模块密码、波特率及固件版本；本地监听返回成功或服务发现成功均不能单独作为“可收发”的依据。

**临时调试入口。** 在现有设备详情页提供HEX输入及单次发送、HEX接收内容/长度/时间、本次连接累计收发字节数、清空及复制记录、初始化失败阶段与错误提示。重连后区分历史与本次数据；调试入口可在正式版本隐藏，但实际收发及错误反馈须保留。

#### 公共帧

以下多字节整数均为无符号、小端；不直接序列化C结构体，不依赖padding。帧头不转义，依长度与CRC定位。DFB1承载数据，Android当前17字节写入分片与手表16字节UART读取均只作传输块，均不代表帧边界。

| 帧偏移 | 字段 | 宽度 | D1取值/解释 |
| --- | --- | --- | --- |
| 0 | magic | 2 | 固定A5 5A |
| 2 | version | 1 | 01；不同布局版本不兼容 |
| 3 | kind | 1 | 00请求，01应答；本轮无主动业务事件 |
| 4 | cmd | 1 | 01 DeviceInfo，02 GetStatus，03 SetTime |
| 5 | sequence | 2 | 1..65535，同一session内严格递增；应答原样关联 |
| 7 | session | 4 | 手机选择的非零会话标识；应答原样关联，不是密钥或认证 |
| 11 | payload_length N | 2 | 0..128，仅载荷长度 |
| 13 | payload | N | 按下表定义 |
| 13+N | crc32 | 4 | 覆盖帧偏移0..12+N，共13+N字节；CRC本身不参与 |

总长17+N，最大145字节。CRC采用现有`code/System/crc32.c`：反射多项式0xEDB88320，init/xorout均0xFFFFFFFF；校验向量ASCII 123456789→0xCBF43926，线上尾部26 39 F4 CB。CRC只查传输完整性，不提供配对、身份认证或授权。首轮为受控台架单手机通信，产品访问控制另行确认。

接收按字节推进并有界保留至多145字节候选：搜索A5 5A，读满13字节头后核对版本/kind/长度，再等待17+N字节；CRC通过才分派，随后继续处理剩余字节，故支持跨多次接收的一帧及一次接收多帧。长度超过128、版本非01或CRC错误，从当前候选起丢1字节后重新找帧头，不信任坏帧的长度跳过后续好帧；CRC错误及未知布局版本均静默丢弃、不发失败回包。尾部单独A5保留等待后续。候选帧字节间隔超过1000ms或从帧头起超过5000ms则废弃并继续找下一候选；UART溢出/错误须使当前候选失效并记诊断，不把残缺帧交业务。精确计时、流控及缓冲峰值均需后续软件测试验证。

应答必须经过统一发送队列按不大于16字节推进，至多每5ms发送一次，禁止业务函数各自抢UART。发送失败不盲目重发半帧，手机按完整应答超时处理。手机也串行排队写入，连接未就绪时不发送；在应用层同时只保留一个未完成请求。

#### 会话、超时、重复请求和错误

手机首先用新非零session、seq=1发空载荷DeviceInfo，只有收到成功应答后才发其他命令；新session的合法DeviceInfo建立/替换当前会话，其他未知session请求返回04 NOT_READY。seq=0或session=0返回02 BAD_VALUE，不建立会话。错误应答沿用请求cmd、sequence、session，kind=01、version=01；不以请求kind=01生成应答。

同一session每个新请求使用更大的seq，不回绕；用尽后重新建session。手表保存最后已处理seq，以及该请求的完整字节与完整应答（含失败应答），缓存30秒，缓存过期不清最高seq。完全相同的最后请求在缓存期内只重发缓存应答，不重执行命令；同seq却内容不同返回07 SEQ_CONFLICT；旧seq或缓存过期的相同seq返回08 REQUEST_EXPIRED，不执行。收到更大seq后旧请求不再可重放。进入执行前先占用该seq，完成副作用及回读后、首次发送前先保存应答，避免回包丢失导致重复校时；正在处理的相同请求不并发执行。忙时返回06 BUSY，手机不得盲重试写操作。

手机从该请求最后一个写入完成回调开始等待完整、CRC正确且cmd/session/seq匹配的应答，超时2000ms；同一连接内最多重试2次（总计3次），重试必须使用同session、同seq及完全相同字节，不重取时间。设备执行时间目标小于应答超时，另经实测确认。缓存应答中的时间是原执行时回读值，重试回包不能当作新采样；手机另发新seq GetStatus查看当前时间。连接断开立即停止重试并撤销就绪；重连后新session执行DeviceInfo→GetStatus，若仍需校时，用新seq和手机当前时间重新发SetTime，不自动续发断线前的写请求。设备复位后RAM去重状态丢失，不承诺跨复位exactly-once；不得因此把旧SetTime自动补发。session不是链路状态检测或多客户端访问控制。

成功应答载荷第0字节为00，并附命令数据；失败应答载荷只含1字节错误码，不附看似有效的数据。线上的错误码独立定义，不能直接强转watch_status_t：

| 错误码 | 含义与手机动作 |
| --- | --- |
| 00 | OK；仍按命令检查长度及字段有效性 |
| 01 | BAD_LENGTH：命令载荷长度不符，修正请求 |
| 02 | BAD_VALUE：时间越界、零session/seq等，修正参数 |
| 03 | UNSUPPORTED：CRC正确、版本01但命令不支持，停止调用 |
| 04 | NOT_READY：会话或RTC未就绪，重新查询/初始化，不假报成功 |
| 05 | IO_ERROR：RTC/驱动读写失败，查询状态后由用户决定重试 |
| 06 | BUSY：本次未执行，稍后使用新seq，写请求须先查状态 |
| 07 | SEQ_CONFLICT：相同seq不同内容，修正请求序号 |
| 08 | REQUEST_EXPIRED：旧请求或重放缓存过期，先查询再发新请求 |
| 09 | INTERNAL：内部状态/编码异常，保留失败状态并诊断 |
| 0A | TIMEOUT：底层操作超时，先查询当前状态，不能推定没发生副作用 |

参数错误不触碰RTC；若写入后回读失败，只返回相应错误，手机必须认为结果未知并查询，不能假定RTC未改变。WATCH_OK→00、INVALID_ARGUMENT→02、NOT_IMPLEMENTED→03、NOT_READY→04、IO_ERROR→05、TIMEOUT→0A、INVALID_DATA→05；其他内部错误→09。帧CRC失败不返回上述错误码。

| 固件升级 | 用户选择兼容固件文件；显示版本和大小；发送分片、处理偏移应答、重传和断线恢复；展示传输、校验、重启、升级结果 | F19 | 文件完整校验后才允许进入升级阶段；失败不显示成功；重启重连后读回实际版本；本次不要求固件下载服务器 |

抬腕识别、按键唤醒、超时熄屏、运动与PPG采样、低活动算法、低电滞回、STOP和唤醒恢复由手表端负责（F04/F05/F08/F09/F13/F14），手机端展示相关状态。本期手机端范围为Android本地应用及上述功能；新增远程控制项由双方另行确认。

## 手机与手表的接口清单

方向以手机为参照。下表列出接口字段；具体字节布局在APP-03中共同确定。

| 逻辑接口 | 方向 | 请求/事件内容 | 应答/上报内容及约束 |
| --- | --- | --- | --- |
| 设备信息 `DeviceInfo` | 请求→应答 | 查询设备信息 | 稳定设备标识、硬件型号/版本、App固件版本、协议版本、支持能力；OTA另需镜像兼容与Boot能力信息，确切字段待冻结 |
| 当前状态 `GetStatus / StatusChanged` | 查询→应答；手表→手机 | 查询状态；是否周期订阅及其频率待定 | 时间与有效性、日期对应的步数、电池mV及估算%、心率bpm、估算血氧%、各测量有效性、更新时间；若要展示接触质量须增加质量状态定义，不能由手机猜测 |
| 校时 `SetTime` | 请求→应答 | UTC Unix秒（1970-01-01 00:00:00起点）；2026-11-07用户确定本地固定北京时间UTC+8，不使用夏令时 | 成功/失败及设备实际保存时间；本地显示、日期切换与按日步数统一使用UTC+8，不随手机时区变化 |
| 参数读取 `GetSettings` | 请求→应答 | 查询当前参数 | 定时提醒设置、低活动提醒时长及可支持范围/版本；支持启用开关、数量和默认值须共同确认 |
| 参数保存 `SetSettings` | 请求→应答 | 需要修改的提醒参数 | 参数是否合法、是否持久化成功、实际保存值；不能只依据BLE写入成功就判断参数保存成功 |
| 历史查询 `GetHistory` | 请求→分页应答 | 游标/起始记录、页大小；日期过滤是否由设备支持待定 | 记录唯一标识、类型、时间、值及单位/有效性、下一游标和结束标志；约定覆盖环形存储后游标失效行为，不能默默跳过 |
| 求助事件 `SafetyEvent` | 手表→手机 | 事件ID、来源（手动/跌倒）、发生时间及有效性、阶段（待确认/已发起/已取消等） | 手机按ID去重并更新阶段；断线期间是否存储、如何补报及去重生命周期待约定 |
| 接收确认 `EventAck` | 请求→应答 | 已收到的事件ID | 只证明手机收到设备事件，不证明用户拨号/短信发送或接收方送达；ACK与重传规则待冻结 |
| 升级开始 `OtaBegin` | 请求→应答 | 镜像目标硬件、版本、长度、整包CRC；镜像头格式待定 | 是否可升级、拒绝原因、支持片长和设备确认的接收偏移；设备端负责容量及兼容性判断 |
| 升级分片 `OtaChunk` | 请求→应答 | 本包偏移、实际数据长度和数据 | 设备确认的连续接收偏移/失败原因；重传重复包应可识别，片长受实际传输能力约束 |
| 升级查询 `OtaQuery` | 请求→应答 | 查询当前升级会话 | 当前镜像标识、状态、已确认偏移、错误；只有同一镜像才能续传，不能仅依据手机本地进度恢复 |
| 升级结束 `OtaFinish` | 请求→应答及重连查询 | 请求完整校验并进入升级流程 | 校验结果、是否进入重启/安装、失败原因；最终成功以重连后的设备版本和升级结果确认，传输100%不等于升级成功 |

手机端管理本地联系人、CSV保存分享和短信/拨号调用；手表端负责离线本地提示。双方确定重连后的事件补报流程。

## 双方交付与联调边界

手机端负责人交付Android工程、可安装APK、对应源码版本、支持的系统范围及尚未支持的接口；手表端提供对应固件版本、真实BLE通道参数、双方确认的帧与载荷定义、可复算的收发样例和功能状态。样例作为本节正式接口说明维护，不另留临时测试报告。

联调顺序：设备连接与信息查询 → 状态和校时 → 提醒参数 → 历史和CSV → 健康状态 → SOS/跌倒 → OTA。每次注明APK与固件版本，依次检查正常及失败应答、断线重连和重复消息处理。
