### 设备命名配置

为便于扫描识别，当前配置固件为`F06-NAME-20261116-02`，镜像为`code/Build/Objects/smart_watch_F06-NAME-20261116-02.hex`，同名BIN/AXF保留至实测结束。它沿用同一Keil工程和smart_watch目标，临时令`WATCH_BLE_NAME_SETUP=1`构建；源码默认仍为0。为方便Keil直接下载，标准镜像曾临时切换为02配置版；2026-11-16用户确认MODULE ACK OK后，已将标准`smart_watch.hex`及BIN/AXF恢复为普通验收版，等待用户重新下载。普通镜像另完整保留为同目录`smart_watch_F06-P01-20261115-01.{hex,bin,axf}`，普通BIN与原F06-P01-20261115-01的SHA256一致。

实测阻碍：01版已烧入并显示BLE NAME SETUP，用户短按KEY后报告NO ACK TIMEOUT；随后确认模块RX→PA9、TX→PA10。此结果只说明未收到预期应答，不能归因于接线错误，也不证明模块不支持UART配置。01版只覆盖旧版拨动AT开关进入流程，缺少新版软件进入流程，已由02版替换。

配置时保持既有3.3V/GND/TX/RX接线、模块USB空置、手机不连接模块；旧版需要断电拨AT档，新版忽略该开关。烧录02专用HEX后屏幕标题为BLE NAME SETUP 02。短按板载KEY后显示CONFIGURING，先发送只读`AT+NAME=?\r\n`确认旧版命令模式；只有查询超时才安静等待1秒，发送一次不带换行的`+++`，必须收到完整Enter AT Mode提示才继续。确认命令模式后，仅发送一次`AT+NAME=SmartWatch\r\n`。各交互阶段最多2秒，整次确认含进度显示约不超过8秒；错误和超时不自动重试。界面区分ENTER AT TIMEOUT、SET NAME TIMEOUT及NO RX BYTES/RX DATA SEEN；OK仅显示MODULE ACK OK，不把应答当作广播名实测通过。配置页持续亮屏，普通透传和振动/运动任务不运行；掉屏后节流重试显示，状态保留。

收到ACK后断电拨回NORM，将备份的普通镜像恢复至标准`smart_watch.hex`/BIN/AXF并烧录，再在手机App重新扫描，须以实际出现`SmartWatch`及断电后消失/上电后重新出现确认设备身份和名称保存。若未收到ACK，按失败阶段和是否收过UART字节继续定位，不盲目更新模块固件。[原厂TEL0073配置说明](https://wiki.dfrobot.com/tel0073/docs/22555)明确区分V1.7及以前的AT开关与V1.8及以后的+++进入流程；[原厂命令表](https://wiki.dfrobot.com/tel0073/docs/22272)列出AT+NAME、名称上限13字节。实物模块固件版本仍未知，不因手册版本推定已确认。

## 资料

### 2026-11-16 BLE实物联调检查点

- 普通固件F06-P01-20261115-01已恢复并由用户确认显示BLE UART CHECK。改名02已获MODULE ACK OK；随后nRF Connect发现并连接设备，标签显示SMARTWATCH，地址`0C:B2:B7:4E:A2:35`，状态CONNECTED / NOT BONDED。原始广播名大小写及另一次完整断电后的保存仍需单独核实，不能把界面标签当作原始广告包。
- 实际服务为`0000dfb0-0000-1000-8000-00805f9b34fb`；特征DFB1与DFB2完整UUID使用同一基础UUID，均显示Notify、Read、Write、Write No Response。两者在本次服务发现中都只有User Description `0x2901`，没有CCCD `0x2902`；不能据此推定所有版本模块都如此。
- 用户向DFB1写入十六进制`31 32 33 34`后报告手表RX和TX各增加4，证明本次手机写入经过模块到达手表，且手表已将4字节交给UART回显发送。DFB1单次读取只得到`31`，这不是完整回显接收证据，也不能据此判定另3字节丢失。
- 用户在普通BLE页短按MENU后报告TX增加11，对应手表发送`WATCH BLE\r\n`；手机日志没有出现该数据接收。nRF Connect启用CCCDs后，仅成功启用Generic Attribute的2A05指示；对DFB1、DFB2明确报Unable to configure notifications。末尾All services enabled不表示这两个通道订阅成功。手表→手机原始通知回传尚未通过。
- 原厂Android示例`BluetoothLeService.java`第514行附近直接调用Android `setCharacteristicNotification(characteristic,true)`，写CCCD代码被注释；BlunoLibrary经型号/命令通道初始化后对DFB1启用本地通知监听。下一步由手机端负责人核对现有APK是否实际注册DFB1本地监听，缺少2902时提供此实物版本的兼容路径，记录API返回值及onCharacteristicChanged原始字节。不能把“无CCCD”一律判断为连接失败，也不能把本地监听返回true当作收到数据；有CCCD的其他设备仍按标准配置流程处理。命令通道初始化是否必要须实测，不自动改模块参数或照搬示例字符串/并发写入。

当前仍待：队友APK连接/通知适配与真实双向收发、原始字节完整性及断线恢复等验收，以及队友可构建工程证明。nRF Connect的局部结果不替代队友APK验收，不放行F06-P02。

### F06-P01 接入准备

首步仅验证UART与BLE双向原样透传，保留业务帧、CRC和命令分发至F06-P02。手表USART1的候选测试配置为115200/8N1；它是当前工程配置，不是已确认的模块实物默认值。旧UART回环任务必须退出，只有BLE任务领取串口接收数据，不自动发送AT指令、不升级模块固件。没有接入模块链路状态信号时，UART可用或发出字节均不能证明手机已连接。

官方模块说明及本地引脚图均标明3.3V、TX、RX、GND，接线沿用表格：模块TX→PA10，模块RX→PA9，3.3V→3V3，GND共地；按模块丝印匹配，不凭两排排针位置推断。透传测试使用NORM档，AT档是配置通道；BOOT用于模块升级，本步不操作。USB与3.3V引脚不在本轮并行供电。原件图见originals.zip内蓝牙透传模块/TEL0073_wiki_02.png，当前官方产品页已重新核对供电/引脚/透传说明。实际模块版本、串口参数和GATT服务/特征仍需用户与APK发现验证，不能直接冻结示例UUID。

P01验收固件的约定：APK发来的字节在UART侧被有界读取并原样回显，包含00、FF、CR和LF；一次读取/一次通知不表示一个完整业务帧。手表不自动发送心跳或AT，亮屏BLE页MENU短按请求发送一次ASCII `WATCH BLE\r\n`（11字节），用于核对手表→手机。手机端比较实际收到的字节与发送内容，不把本地GATT写入成功当作双向透传通过；帧头、CRC、请求序号及业务命令仍未冻结。该约定仅用于P01验收，正式业务通信属于F06-P02及后续步骤。

### F06-P01 实现及软件验证（2026-11-15）

现有工程增加BLE默认诊断页，KEY长按循环BLE、姿态、计步、MPU、振动、时间六页；10秒熄屏及原页面操作沿用。原UART回环任务和清空接收缓冲操作已移除，由BLE任务每5ms至多读取16字节、写入一次，接收内容优先原样回显，无数据不主动发送。MENU短按发送只保留一个待处理请求，在无回显周期发送；错误不盲目重试可能已部分发送的数据。串口、总线及其他模块分工未变，没有修改底层UART、姿态/计步算法、Keil工程或编译清单。

页面RX B/TX B分别是UART层已读取/完整发送成功字节数；不等于手机已收字节数。LAST显示最近一次UART读取的前4字节HEX，不代表一帧；接收错误后旧预览清除，无新数据时保留历史标识。错误计数显示两层计数中的较大值、上限显示99999+，并非两者求和。LINK UNKNOWN表示未接入真实链路状态信号；`ble_link_connected`明确返回NOT_IMPLEMENTED且输出false，false在此不表示已测得断开。收包不会自动唤醒或续亮屏幕。

42项链路断言及310项主循环/UI断言通过，覆盖任意字节/拆分/空读、16字节上限、错误恢复、失败不计整包成功、计数饱和、回显优先与单次发送、三键唤醒隔离、六页/原操作、编辑草稿/掉屏恢复和时基回绕；UI帧预览已核对。严格主机语法与Keil固定smart_watch目标0错误0警告；57项C/汇编工程条目中Boot明确排除，实际56项编译/汇编输入未变。BIN 24496字节、SHA256 `bbf2c7ae1b7544ae31ca1aa807dec063c0eda404efd3494f495af5a60bfc200c`，版本及首启向量核对通过。这些是软件检查，不证明实际模块、BLE连接、吞吐或APK收发已通过。

实物验收先断电接线，移除可能残留的PA9—PA10回环短接，模块NORM档、3.3V供电且USB留空；接好后再烧录本版。实际服务UUID、写/通知特征及权限、串口参数、手机/模块版本均按APK实测记录。已有测试APK尚不能替代计划要求的队友可构建源码/构建证明；相关缺项未完成前不放行F06-P02。
